# دستیار فروش دیوار

ربات پاسخ‌گوی خودکار و پنل وب برای فروشندگان دیوار، متصل به API «کنار دیوار».

این پروژه با هدف خودکار کردن پاسخ به پرسش‌های تکراری خریداران ساخته می‌شود. فروشنده فهرست کالاها و قیمت‌های خود را مدیریت می‌کند، آگهی‌هایش را از دیوار دریافت می‌کند و گفتگوهای مرتبط با آن‌ها را در یک پنل فارسی می‌بیند. ربات نیز بر اساس اطلاعات همان فروشنده به پیام‌های خریداران پاسخ می‌دهد.

> **وضعیت پروژه:** در حال توسعه است و هنوز نباید آن را یک سرویس آمادهٔ استفادهٔ عملیاتی در نظر گرفت. امکانات پیاده‌سازی‌شده و برنامه‌های آینده در بخش‌های جداگانه توضیح داده شده‌اند.

## پروژه چگونه کار می‌کند؟

۱. فروشنده با گزینهٔ «ورود با دیوار» و جریان OAuth وارد حساب خود می‌شود.

۲. کالاها و قیمت‌ها را در پنل ثبت می‌کند یا فهرست آن‌ها را از فایل Excel وارد می‌کند.

۳. آگهی‌های حساب دیوار خود را همگام‌سازی می‌کند و وضعیت موجودی هر آگهی را مشخص می‌کند.

۴. پیام خریدار از طریق وبهوک دیوار به برنامه می‌رسد. برنامه آگهی و فروشندهٔ مربوط به آن را پیدا می‌کند و برای آگهی‌های موجود و فعال، پاسخ ربات را در همان گفتگو ارسال می‌کند.

۵. فروشنده می‌تواند گفتگوهای ثبت‌شده، تاریخچهٔ پیام‌ها و اطلاعات اشتراک خود را در پنل مرور کند.

برای نمونه، وقتی خریدار دربارهٔ قیمت یک کالا می‌پرسد، ربات نام کالا را در فهرست همان فروشنده جستجو می‌کند. اگر نام دقیق پیدا نشود، از تطبیق تقریبی نام‌ها استفاده می‌کند و در صورت وجود گزینه‌های نزدیک، آن‌ها را پیشنهاد می‌دهد.

## امکانات پیاده‌سازی‌شده

- **پنل فارسی و راست‌به‌چپ:** صفحهٔ معرفی، صفحهٔ طرح‌ها، ورود و داشبورد فروشنده.
- **ورود با دیوار:** احراز هویت OAuth و مدیریت نشست با JWT و کوکی تمدید نشست.
- **مدیریت کالاها:** مشاهده، جستجو، افزودن، ویرایش، حذف و وارد کردن فهرست کالاها از فایل `.xlsx`.
- **مدیریت آگهی‌ها:** دریافت و همگام‌سازی آگهی‌های فروشنده از دیوار و تغییر وضعیت موجودی آن‌ها. ربات برای آگهی حذف‌شده از دیوار یا آگهی ناموجود پاسخ نمی‌دهد.
- **پاسخ‌گویی قاعده‌محور:** تشخیص پیام‌های مربوط به قیمت، سلام و احوال‌پرسی، گارانتی و راهنمای تماس با پشتیبانی؛ جستجوی نام کالا و پیشنهاد نام‌های مشابه.
- **مرور گفتگوها:** فهرست گفتگوهای مرتبط با آگهی‌ها و مشاهدهٔ پیام‌های ثبت‌شدهٔ خریدار و ربات.
- **طرح و میزان مصرف:** ایجاد اشتراک آزمایشی اولیه و نمایش وضعیت اشتراک، دورهٔ اعتبار و تعداد گفتگوها و پیام‌های خریداران.
- **پشتیبانی از چند فروشنده:** فهرست کالاها، آگهی‌ها و گفتگوها به حساب فروشندهٔ مربوط به خود وابسته‌اند.

**نکتهٔ وارد کردن Excel:** فایل باید ستون‌های `product` و `price` داشته باشد. وارد کردن فایل، کل فهرست کالاهای همان فروشنده را جایگزین می‌کند؛ این عملیات افزودن تدریجی به فهرست قبلی نیست.

## محدودیت‌های نسخهٔ فعلی

- موتور پاسخ‌گویی فعلی **قاعده‌محور** است و هنوز از مدل زبانی یا هوش مصنوعی مولد استفاده نمی‌کند. تاریخچهٔ گفتگو ذخیره می‌شود، اما فعلاً در تولید پاسخ کاربرد ندارد.
- مسیرهای ورود با کد یک‌بارمصرف وجود دارند، اما سرویس ارسال پیامک واقعی متصل نشده است. ورود پیامکی در رابط کاربری غیرفعال است و ورود با دیوار مسیر قابل استفادهٔ فعلی است.
- نمایش طرح‌ها، اشتراک و میزان مصرف پیاده‌سازی شده، اما خرید و پرداخت آنلاین، تمدید اشتراک و اعمال خودکار محدودیت مصرف هنوز تکمیل نشده‌اند.
- برخی پیام‌های پیش‌فرض ربات و اطلاعات پشتیبانی نمونه هستند و باید پیش از استفادهٔ واقعی بازبینی و تنظیم شوند.
- ارتباط واقعی با دیوار به تنظیم برنامه در پنل کنار، مجوزهای API و OAuth و نشانی عمومی مناسب برای دریافت وبهوک نیاز دارد.

## مسیر توسعه

کارهای بعدی بر تکمیل امکانات فعلی تمرکز دارند:

- تکمیل مدیریت اشتراک و اعمال محدودیت‌های مصرف.
- اتصال به سرویس پیامک واقعی و تکمیل ورود با کد یک‌بارمصرف.
- افزودن پاسخ‌گویی مبتنی بر هوش مصنوعی با استفاده از اطلاعات فروشنده و سابقهٔ گفتگو.
- تکمیل فرایند خرید، پرداخت و تمدید اشتراک پس از آماده شدن زیرساخت مربوط به آن.

ایده‌های بلندمدت نیز شامل مدیریت پرسش‌های متداول، ارجاع گفتگو به پشتیبان انسانی، گزارش‌های تحلیلی و پشتیبانی از پیام‌های رسانه‌ای است. این موارد امکانات فعلی پروژه نیستند و زمان انتشار مشخصی برای آن‌ها تعیین نشده است.

## فناوری‌های استفاده‌شده

- **Python و FastAPI:** هستهٔ برنامه و APIها؛ تصویر Docker فعلی از Python 3.14 استفاده می‌کند.
- **PostgreSQL، SQLAlchemy Async و Alembic:** ذخیره‌سازی داده‌ها و مدیریت تغییرات پایگاه داده.
- **Pydantic و pydantic-settings:** اعتبارسنجی داده‌ها و مدیریت تنظیمات.
- **HTTPX:** ارتباط غیرهمزمان با API دیوار.
- **pandas و openpyxl:** خواندن فایل‌های Excel.
- **RapidFuzz:** تطبیق تقریبی نام کالاها.
- **Jinja2، CSS و JavaScript ساده:** صفحات وب، بدون سرویس جداگانهٔ فرانت‌اند یا مرحلهٔ ساخت آن.
- **pytest و pytest-asyncio:** تست‌های برنامه و مسیرهای غیرهمزمان.

## اجرای محلی

برای اجرا به Python، محیط مجازی پروژه با نام `.venv` و یک پایگاه دادهٔ PostgreSQL نیاز دارید. اگر فایل `.env` ندارید، یک نسخه از [`.env.example`](.env.example) بسازید و تنظیمات لازم را مطابق آن و [`config.py`](config.py) وارد کنید.

پس از آماده کردن محیط مجازی و تنظیم اتصال پایگاه داده، از ریشهٔ مخزن در PowerShell اجرا کنید:

<div dir="ltr">

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m uvicorn main:app --reload
```

</div>

صفحهٔ اصلی برنامه در `http://localhost:8000` و مستندات تعاملی API در `http://localhost:8000/docs` در دسترس خواهند بود. راه‌اندازی محلی به‌تنهایی به معنی دریافت پیام از دیوار نیست؛ نشانی‌های OAuth و وبهوک باید در پنل کنار نیز تنظیم شوند.

برای اجرای تست‌ها از همان محیط مجازی استفاده کنید:

<div dir="ltr">

```powershell
.\.venv\Scripts\python.exe -m pytest
```

</div>

**اطلاعات محرمانه:** کلیدهای API، توکن‌ها، شماره‌های واقعی کاربران و اطلاعات اتصال پایگاه داده را در فایل‌های عمومی، نمونه‌ها یا تاریخچهٔ Git قرار ندهید. فایل `.env` برای تنظیمات محلی است و نباید منتشر شود. پیش از استفادهٔ عملیاتی، [چک‌لیست امنیت و آماده‌سازی انتشار](plans/CHECKLISTS.md) را بررسی کنید.

## ساختار مخزن

- [`api/`](api/): مسیرهای احراز هویت، وبهوک، فروشنده و صفحات وب.
- [`services/`](services/): منطق ربات، جستجوی قیمت، ارتباط با دیوار، همگام‌سازی آگهی‌ها و اشتراک.
- [`models/`](models/)، [`db/`](db/) و [`alembic/`](alembic/): مدل‌ها، اتصال و مهاجرت‌های پایگاه داده.
- [`schemas/`](schemas/): ساختار و اعتبارسنجی درخواست‌ها و پاسخ‌ها.
- [`templates/`](templates/) و [`static/`](static/): قالب‌های HTML و فایل‌های CSS و JavaScript.
- [`tests/`](tests/): تست‌های برنامه.
- [`docs/`](docs/): مستندات مرجع API کنار دیوار.
- [`plans/PLAN.md`](plans/PLAN.md): نقطهٔ شروع برنامهٔ توسعه؛ وضعیت فعلی در [`plans/STATUS.md`](plans/STATUS.md) ثبت شده است.
